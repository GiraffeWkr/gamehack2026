# 扎德：轨道射手（Zad: Orbital Marksman）· Web 移植版

一个面向移动端的《扎德：轨道射手》（基于 Samharia Studios 的 Zad Archery）网页重制版，基于**反编译**的原始游戏编写。技术栈为 **TypeScript + Vite + PixiJS**，不依赖任何游戏引擎。

当前是一个**战斗垂直切片（vertical slice）**：验证了渲染管线、触控瞄准方案、数值系统、等级曲线以及手机视口下的性能表现。美术已整体替换为统一的 **16-bit 像素风**（见 [像素风美术替换说明.md](像素风美术替换说明.md)），音频仍未加入；**数值全部来自原版**。

## 运行方式

```bash
npm install
npm run dev        # http://localhost:5173（同时绑定 0.0.0.0 便于手机联调）

```

手机测试：同一 Wi-Fi 下打开 Vite 输出的 `Network:` 地址。游戏为**横屏**设计，竖屏会提示旋转。

## 数值与难度（重设计）

旧版把原版 30 关的敌人血量表原样搬来，却没有搬原版撑起这条曲线的装备/锻造系统。
实测：第 7 关起单只小怪要打十几秒，第 20 关之后即使把能买的天赋全买了也打不动。
现在的曲线是围绕"玩家实际能拿到的战力"重新解的：

- **装备战力层**：`Damage ×1.45/关`、`Health ×1.32/关`，在属性面板里可见，天赋树乘区叠加其上；
- **敌人曲线**：血量 4 → 940 万（×1.42/关）、伤害 2 → 2.7 万（×1.28/关）、金币 ×1.45/关；
- **按距离刷怪**：只生成前方 1600 单位内的波次，不再是整关 128 只一起激活；
- **40 关 + 4 个 BOSS**：10/20/30/40，BOSS 作为关底的门；
- **10 种小怪**：5 个家族 + 每族 1 个带机制的精英（减伤 / 吸血 / 召唤 / 爆破 / 疾行）；
- **天赋树价格软上限**：让原版 5×10¹⁴ 的后期乘区节点在 40 关内买得起。

完整推导、旧数值体检与自动试玩数据见 [note/数值体系重设计.md](note/数值体系重设计.md)。
验证：`node tools/playtest.mjs`（机器人 9/9 关通关）、`npm run verify`（353 项断言）。

## 武器与题材（弓 → 能量卡宾枪）

原版是西幻弓箭手，本作的世界已经是太空站、机甲与虫洞。让主角继续拉弓，是整套美术里最后一处出戏的地方；
参考策划案 §4.1 也直接把"落箭"换成了**轨道打击**。因此这一版把武器表现整体换掉：

- 主角改为手持**能量卡宾枪**（5 套配色重画，弓位 → 枪口位，常量 `MUZZLE`）；
- 自动射击 = 卡宾枪点射，弹体是**短弹丸**（`Bolt.png`，约角色 1/3 高）；
- 点击 = 呼叫**轨道打击**（原"箭雨"），落下的是**轨道长矛**（`OrbitalLance.png`，与枪弹分开两张贴图），弹药 = **能量弹匣**（原"箭匣"）；
- 可见文案统一经 [`core/lexicon.ts`](src/core/lexicon.ts) 把旧术语改写为枪械术语，
  生成的数据表（`treeData.ts` / `jobData.ts`）一行未改；
- 内部逻辑 id（`archerSpawned` 等）保持不变；出箭点常量 `BOW` 仅代码内改名为 `MUZZLE`。弹体贴图已从 `Arrow1` 拆为 `Bolt`（枪弹）与 `OrbitalLance`（轨道打击），并删除了 `T_Arrow` 系旧资源。

机制与数值完全不变：射速、伤害、弹药、冷却、轨道打击半径都沿用原参数。

## 存档与恢复

进度存在 **localStorage**（键 `zad-archery-web/save/v1`）：关卡、金币、击杀、已击败守卫、玩家等级/经验、**天赋树**、职业与技能等级、精通、爪兽/蝠群宝石、传送门信标及其已领取关卡。

- **写入时机**：过关、切后台/关页（`visibilitychange` / `pagehide` / `beforeunload`），以及**每 5 秒自动快照**——进程被强杀最多丢约 5 秒；
- **读取**：启动时经 `normalizeSave()` 归一化，损坏或旧版存档会降级为可玩的新档，而不是启动失败；
- **同一来源**：localStorage 按 origin 隔离，`localhost:5173`、`127.0.0.1:5173`、局域网 IP、换端口都是不同存档。请固定用同一个 URL 打开；
- **重置**：右上角重置按钮会删除存档并回到第 1 关；
- 调试参数 `?level=N` 只临时覆盖本局关卡，不会主动写回存档。

> 修复记录：`saveNow()` 一直写入天赋树/职业/精通，但读取时漏带这三个字段——重启后关卡和金币还在，天赋树却被清空。现在读写统一走 [`src/core/save.ts`](src/core/save.ts)，并有 8 条回归断言覆盖往返与损坏存档。

## 扩展前需要知道的两件事

### 1. 数值键是「变量名」，不是 `functionName`

原版用**变量名本身**作为数值字典的键，层类型作为独立参数传入：

```csharp
stats.ChangeAStat("Damage", StatsProperties.Flat, 1.0, IsAdd: true);
stats.Damage.Total.RealValue
```

`StatInfo.functionName`（`"Damage" + "Flat"` = `"DamageFlat"`）只是**工具提示的本地化键**，不是字典键。搞错会导致各层互相找不到、静默只返回 Flat 值。因此本移植版用：

```ts
stats.change('Damage', StatsProp.Flat, 1, true);
stats.get('Damage');                          // Total
stats.layer('Damage', StatsProp.Flat);        // 单层
```

公式（抄自 `StatsDouble.CalculateTotal`）：

```
Total = round( Flat * (1 + Additive/100) * Multiplicative )
```

小于 1000 保留两位小数，大于等于 1000 取整。`Multiplicative` 是**连乘**，初始为 1——未设置该层会把数值归零。

### 2. 相机以角色为锚，而不是以相机自身为锚

角色必须能一路走到关卡传送门，而传送门在最后一批敌人倒下前始终保持在屏幕右缘之外。若改为钳制**相机**，角色会被推出屏幕。正确写法见 `renderer.updateCamera`：

```ts
const subjectX = Math.max(game.px, game.portalX - CAMERA.maxLead + CAMERA.additionalLimitAfterPortal);
const desired  = subjectX - CAMERA.cameraLeadX;   // 角色位于中心偏右
```

## 美术与语言

### 当前：16-bit 像素风

`public/art/` 的 192 张被引用图片是程序化生成的像素画，调色板、栅格、描边规则见
[像素风美术替换说明.md](像素风美术替换说明.md)；重跑用 `node tools/gen-art-pixel.mjs`
（`--only=bg|chars|fx|ui|tree` 可只重做一组）。画布尺寸与原素材逐文件一致，
所以代码里的世界高度、锚点、视差取景都不用动。

**关键渲染约定**：所有纹理由 Pixi 以 `nearest`（`src/render/renderer.ts`）采样，
DOM 图片走 `image-rendering: pixelated`——两者都不能改回线性过滤，否则像素块会被插值糊掉。

### 原版素材的导出方式（保留备查）

`public/art/` 下的资源均用 UnityPy 从 `Zad Archery_Data` 提取：

| 资源 | 来源 |
|---|---|
| `BG1_*` / `BG2_*` | 8 层视差背景，作者规格 **1920x600** |
| `Archer_1..5` | 玩家射手（能量卡宾枪），5 套皮肤，悬浮待机姿势 |
| `Guardian_*`, `bat_swarm_0` | 小怪美术 |
| `king_boss` | 尚未移植的最终 Boss |
| `T_Arrow`, `T_GlowOrb_Bullet`, `FX_TX_*`, `FX_Ring_AD`, `shockwave`, `orb` | 特效 |

背景精确为 **1920x600**，故以此为参考分辨率，相机水平方向始终可见 1920 世界单位；垂直范围随设备宽高比变化，与原版正交相机的取舍一致。

图层深度由资源名决定——`BG1_0sky` 最远，`BG1_7item` 最近且绘制在角色之前。需要重新提取时执行：

```bash
python analysis/export_sprites.py     # 切片 Sprites -> PNG + 清单
python analysis/export_bg.py          # 视差图层
```

## 动相机前必须理解的一点

**世界 Y 向上增长，且与美术共用同一坐标系**：地面为 `0`，天空为 `+600`。刻意不做“美术坐标”与“游戏坐标”之间的符号翻转——之前正是这种错位导致整个背景被画到视口上方。

Pixi 局部坐标 Y 向下，渲染器在放置精灵父容器时翻转一次 Y，写入世界坐标时再翻转一次：

```ts
c.y = groundScreenRow;      // 世界 Y=0 落在角色脚底行
sprite.y = -worldY;         // 世界向上 -> 局部向下
```

**不要**试图用负缩放（`c.scale.y = -s`）修正——那会镜像所有精灵。

相机以**角色**为锚而非地面行。可见世界高度随宽高比变化，而地面 Y 不变，若锚定地面，矮视口上美术和角色都会被推出屏幕：

```ts
// 角色脚底的屏幕行：
this.viewH * CAMERA.playerScreenFraction
```

`cameraLeadX`（300）是相机落后角色的距离，使他的脚落在约 40% 屏宽处——大部分画面是他将要走入的地面。

运行游戏时加 `?measure=1` 可查看各图层屏幕范围 + 角色位置的实时几何覆盖层。

## 移动端说明

- **仅横屏。** 这是横版卷轴游戏，竖屏显示旋转提示。
- **安全区**通过 `env(safe-area-inset-*)` 处理——原版在 `SafeAreaManager` 里用写死的 iPhone 边距。
- **拇指可达性。** 唯一可交互元素是右下角技能轮盘与左下角弹匣读数。屏幕中部没有任何控件，因为整个可玩区域都是瞄准目标。
- **固定 60Hz 时间步**（`Game.tick`），120Hz 手机行为一致，GC 卡顿不会瞬移模拟。
- 精灵**回收复用**而非每帧新建；粒子池化；浮动伤害数字为池化 DOM 节点，每帧上限 128。

- **天赋树遮挡**：底部 HUD 曾挡住根节点下方的节点，现面板打开时底部栏上移且指针穿透，节点可正常点击。

### 表现修复（像素风替换后）

- **射箭轨迹**：出箭点原先沿用画布像素值 `(46, 132)` 当世界单位，而角色只有 99 单位高，箭实际从**头顶上方**发出；现按 25×30 像素网格换算为 `(30, 58)` 的弓位。箭身朝向改为按屏幕速度 `atan2(-vy, vx)` 计算（旧公式把下行箭画成上仰约 2 倍弹道角），落箭雨改为箭头朝下；弓口闪光由「1.5 倍大的整支箭」改为小星芒，不再像第二支箭。
- **天赋树图标**：白色剪影叠在状态色底上做 multiply，结果等于底色，节点图标与高亮环一直是一块纯色方块；现改为 CSS 遮罩，按状态给剪影/高亮环染色。

- **箭匣读数**：面板打开时箭雨冷却圈与剩余数量仍可见（移到面板上方），数量居中显示于圆圈内。
