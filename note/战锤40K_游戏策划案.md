# 《战锤 40,000：帝皇之锤》游戏策划案

> 本策划案建立在对 Zad Archery（Samharia Studios）的完整逆向分析之上。
> 系统架构、数值模型、成长曲线全部沿用其已验证的框架，
> 题材与表现层替换为战锤 40,000 主题。
> 底层数据来源见 `ZadArchery_游戏策划案.md` 与 `_analysis/`。

| 项 | 值 |
|---|---|
| 工作标题 | 战锤 40,000：帝皇之锤（Warhammer 40,000: Hammer of the Emperor） |
| 类型 | Survivor-like / 反向弹幕 + 高频鼠标操作 |
| 平台 | PC（**itch.io 优先**，理由见 11.1） |

| 性质 | **非商用同人项目**，免费发布 |

## 一、产品定位

### 1.1 一句话

**一款把「幸存者类」的自动战斗，和「审判官呼叫轨道轰炸」的高频鼠标操作
结合起来的战锤 40,000 主题 Roguelite。**

### 1.2 核心幻想

你是一名审判庭的特工，孤身空降到被异形与异端占据的世界上。
你不需要亲手杀光所有敌人 —— 你的武器是**待在上面的那艘船**。

**玩家扮演的不是战士，是「坐标」。**

这个设定把参考项目里「鼠标落箭」的机制解释得非常自然：
你移动躲闪，鼠标指向哪里，死亡就从天上落到哪里。

### 1.3 与参考项目的差异

| 维度 | Zad Archery | 本作 |
|---|---|---|
| 题材 | 弓箭手 + 西幻 | 审判官 + 哥特科幻 |
| 主要伤害来源 | 鼠标落箭（箭雨） | **鼠标标记轨道打击** |
| 基础自动攻击 | 弓箭手平射 | 审判官爆弹手枪 |
| 宠物 | 狼 / 熊 / 隼 | 机仆 / 战斗自动机 / 伺服颅骨 |
| 驯服敌人 | 收编 | **机仆化改造**（击杀后改造成你的单位） |
| 派系 | 5 个职业 | **5 个帝国机构** |
| 敌人 | 怪物 | **5 个异形/异端阵营** |
| 核心操作 | 移动 + 鼠标 | **完全相同** |
| 全部成长系统 | 8 层 | **完全相同（换皮）** |

## 二、世界观与核心设定

### 2.1 设定梗概

第 41 个千年。一支帝国舰队在亚空间中偏离了航线，
抵达了一颗被标注为「已净化」的星球 —— 但地表上挤满了
兽人的部落、泰伦的触须、混沌的祭坛，以及钛族的前哨。

你是一名审判官，带着随从与一艘在轨的打击巡洋舰降落。
你的任务不是求援、不是撤退，而是**在舰队主力到达前，把这个世界清干净**。

每一关 = 你推进到下一个战区。
每一关结束 = 轨道上的舰船对你的表现做出评估，发放补给。

### 2.2 为什么这个设定适配玩法

| 玩法要素 | 设定解释 |
|---|---|
| 玩家自动攻击 | 审判官随身携带爆弹手枪，自动开火 |
| **鼠标 = 落锤** | **标记轨道打击坐标** —— 舰船按你的标记投送火力 |
| 技能自动释放 | 随从与机魂按战斗协议自动执行 |
| 弹药 / 冷却 | 轨道舰船的**火力调度排队** |
| 击杀 → 变友军 | 机械教随行人员把敌人残骸**改造成机仆** |
| 宝箱 | 轨道**补给空投** |
| 宝珠（限时增益） | **圣物**（帝皇的圣髑、异形造物） |
| 每关限时 | 舰船在该轨道的**停留窗口** |

> **设定不是装饰，是给机制一个自洽的解释。**
> 参考项目用「弓箭手」解释了「箭从天上落」，
> 我们用「轨道打击」解释同一件事，而且**解释力更强**：
> 为什么伤害这么高？因为那是舰炮。为什么有冷却？因为要排队。
> 为什么有地图范围？因为那是轨道投影区。

### 2.3 一处需要补强的地方

参考项目的风险提示是「锤的重量感难体现」。本作反而**解决了这个问题**：

轨道打击天然带有**延迟 + 巨响 + 屏幕震动 + 地面焦痕**，
它的重量感比箭雨强得多。设计上要把这个优势用足：

- 标记后 **0.8–1.2 秒延迟**才落地（给玩家「我在呼叫」的掌控感）
- 落地瞬间 **强屏幕震动 + 音爆 + 冲击波扩散**
- 落点留下 **持续数秒的焦痕**（视觉反馈 + 区域占用）
- 齐射时 **多道打击错开 0.1 秒落下**（形成鼓点节奏）

## 三、核心循环（沿用，换皮）

```
进入战区（MonstersLevel → 战区编号）
   ↓
移动躲闪 + 鼠标标记轨道打击 + 随从/技能自动作战
   ↓
击杀 → 掉落王座币 / 各阵营战利品
   ↓
轨道补给空投（装备 / 圣化印记 / 圣典卷轴）｜ 圣物（限时增益）
   ↓
敌人死亡有概率被机械教机仆化，变成你的单位
   ↓
战区清剿完成 → 结算资源
   ↓
局外：点《圣典》、锻造、开采、圣化、晋升机构、星炬祝福
   ↓
推进到下一个战区，难度 +1
```

**关键设计（沿用参考项目）：游戏没有角色经验等级。**
存档里的 `PlayerLevel` / `PlayerExp` 恒为 0，
真正的关卡变量是**战区编号**（原 `MonstersLevel`）。
玩家强度 100% 来自局外的装备与《圣典》，
战区难度独立驱动。

> 这个解耦在 40K 设定下更自洽：
> 审判官不会「升级」，他只会**带更好的装备、调动更大的权限**。

## 四、战斗系统

### 4.1 轨道打击（替代「鼠标落箭」，主输出）

玩家鼠标指向哪里，轨道舰船就把火力投送到哪里。

| 原属性 | 40K 术语 | 作用 |
|---|---|---|
| `NumberOfMouseProjectiles` | 齐射弹数 | 每次投送几发 |
| `MouseMagazineSize` | 火力配额 | 单轮可投送总数 |
| `MouseMagazineRegenTime` | 火力调度周期 | 配额回填时间 |
| `MouseAutoMode` | 自动交战协议 | 免操作自动投送 |
| `MouseNumberOfHits` | 每发命中次数 | 子母弹 |
| `MouseMaxNumberOfEnemies` | 溅射上限 | 单发最多打几个 |
| `MouseChanceForAnotherHit` | 二次引爆概率 | 命中后再炸一次 |
| `MouseChanceToFireSkills` | 联动协议 | 投送时触发技能的概率 |

**「火力配额」是本作的操作核心**：配额有限、要等调度，
玩家不能无脑点击。后期通过《圣典》点出「自动交战协议」才卸掉操作负担。

**40K 视觉表现**：
- 落点先出现**审判庭的标记符**（红色瞄准刻线）
- 1 秒后**光柱贯穿云层**，地面炸开
- 焦痕持续 3 秒，可以当临时“区域占用”用来分割敌群

### 4.2 五大机构（替代 5 个 Job）

**每个机构 3 个技能，共 15 个技能。**

| 机构 | 技能 1 | 技能 2 | 技能 3 | 主题 |
|---|---|---|---|---|
| **星际战士** | 爆弹齐射 | 速射协议 | 热熔炸弹 | 远程爆发 |
| **机械教** | 机械猎犬 | 战斗机仆 | 伺服颅骨 | 召唤 / 仆从 |
| **刺客庭** | 致命瞄准 | 穿甲弹 | 死神之眼 | 单体狙击 |
| **星语庭** | 烈焰圣典 | 闪电圣典 | 霜寒圣典 | 灵能元素 |
| **死灵科技** | 圣甲虫群 | 熵力场 | 坍缩奇点 | 虚空 / 虫群 |

**技能内部分三类（沿用参考项目）**：

1. **主动技能**（有冷却）：爆弹齐射、热熔炸弹、圣甲虫群、熵力场、坍缩奇点 —— 冷却好自动放
2. **召唤单位**：机械猎犬 / 战斗机仆 / 伺服颅骨 —— 持续存在的作战单位，
   有自己的攻击范围、攻速、命中次数、生命倍率
3. **被动触发**：烈焰圣典 / 闪电圣典 / 霜寒圣典 —— 靠概率触发，不占技能位

**每个技能有 4 个强化维度**（以爆弹齐射为例）：
弹数 / 命中次数 / 冷却 / 多发概率。

**技能强度档（Skill Powers）**：每个技能 0–3 共 4 档，
与《圣典》节点一一对应。

**每个技能有 39 个可强化维度**（参考项目实测的强化项全集，节选）：

```
弹数 / 多发概率 / 命中次数 / 瞄准数 / 穿透数 / 折返次数 / 范围
攻速 / 持续时长 / 每击杀延长 / 技能伤害 / 暴击伤害 / 暴击冷却缩减
三倍伤害 / 减速 / 穿透概率 / 集束炸弹 / 灼烧蔓延 / 冰霜倍率
蝙蝠倍率 / 对冰冻目标伤害 / 每回合伤害 / 吸收伤害 / BOSS 伤害
BOSS 免冷却 / 处决阈值 / 新星治疗 / 回复 / 吸血 / 威慑
镜像 / 俯冲概率 / 联动施法 / 闪电链 / 命中触发 / 宠物生命
```

> 参考项目里还留有**一批未在存档中暴露的职业大招**
> （从投射物命名可还原：`Archer1_RoA` 箭雨、`Archer2_Dragon` 巨龙、
> `Knight1_AreaSlash` 范围斩、`Knight2_Spear` 长矛、
> `Ninja1_Shuriken` 手里剑、`Vampire1/VampireExp`、`Vampire2/BloodSuck` 吸血、
> `Lightning1/LChain` 闪电链、`Fire1/Meteor` 陨石）。
>
> 说明参考项目的**技能储备远大于 15 个**，
> 存档只暴露了其中一套。本作可以按同样思路**先做 15 个上线，
> 把其余作为后续更新内容** —— 这张表就是现成的储备清单。

### 4.3 随从 / 机仆化 / 盟友（三条兵力线）

| 系统 | 原实现 | 40K 版本 |
|---|---|---|
| **召唤单位** | Wolf / Bear / Falcon | **机械猎犬 / 战斗机仆 / 伺服颅骨** |
| **机仆化改造** | ChanceToTameEnemiesOnDeath | **击杀敌人有概率被机械教改造成机仆** |
| **帝国援军** | *ChanceToSpawn 属性 | **风暴兵 / 帝国卫队 / 机械教护教军** |

**机仆化（替代「驯服」）** 是本作最有 40K 味道的一环：

> 你把敌人打死后，随行的机械教技术神甫会把残骸拖走，
> 在现场就改造成一台机仆，装上伺服臂和爆弹枪，然后推上战线。
> **上一秒还在向你冲锋的异形，下一秒就在替你挡子弹。**

这条循环在数值上完全沿用参考项目的 `ChanceToTameEnemiesOnDeath`、
`MaxTames`、`TameHealthMultiplier`、`TameDamageMultiplier`。

> ⚠️ **参考项目实测的教训**：驯服系统伤害占比 < 0.6%，
> 玩家感受不到。**本作必须把机仆化的数值权重显著调高**
> （建议目标占比 8–12%），否则同样会被埋没。
> 具体做法：提高 `MaxTames` 上限、提高机仆继承的攻击力百分比、
> 让机仆死亡时爆炸造成范围伤害。

### 4.4 全局战斗参数

```
审判官移速 / 援军攻速倍率
敌人移速倍率 / 敌人攻速倍率 / 敌人生命倍率 / 敌人伤害倍率
攻击距离 / 移动中攻击
```

**「削弱敌人」是一条正经成长线**：玩家可以把 `敌人生命倍率` 压到 0.8、
`敌人伤害倍率` 压到 0.8 —— 在 40K 语境下就是
**「你带着帝皇的威压降临，异形在你面前会本能地畏缩」**。

核心乘区栈（沿用）：
暴击率 / 暴击倍率 / 双重伤害概率 / 三重伤害概率 /
连击概率 / 暴击穿透 / 爆裂弹 / 虫洞弹。

## 五、数值体系（直接沿用，不改）

这一章是整份策划案的**工程底座** —— 纯系统设计，与题材无关，可 100% 照搬。

### 5.1 属性四桶模型

```
Flat                     基础值
AdditiveIncreases        加法百分比 —— 先求和，再 (1 + Σ/100)
MultiplicativeIncreases  乘法因子 —— 直接连乘（1.0 == ×1）
Total                    结算结果
```

**公式（已在参考项目上精确验证）**：

```
Total = Flat × (1 + AdditiveIncreases/100) × MultiplicativeIncreases
```

验证情况：214 个非零属性中 206 个精确匹配，
其余 8 个的偏差全部来自存档把 `Total` 保留两位小数的舍入。

**修改语义有 7 种**（不止「加」，还有「设」）：

```
Flat / Additive / Multiplicative          叠加
SetFlat_And_ResetAddMulti                 设基础值 + 清空加乘层（覆盖语义）
SetFlatOnly / SetAdditiveOnly / SetMultiplicativeOnly
```

### 5.2 属性规模

参考项目有 **273 个属性**，本作按同样方式组织：

| 类别 | 40K 版本示例 |
|---|---|
| 输出 | 伤害、暴击率、暴击倍率、双重伤害、连击、爆裂弹 |
| 生存 | 生命、回复、减伤、闪避、致命免疫、血瓶 |
| 经济 | 王座币获取、掉落率、每秒金币、战利品稀有度 |
| 轨道打击 | 配额、调度周期、齐射数、溅射上限、自动交战 |
| 解锁 | 解锁锻造 / 开采 / 圣化 / 晋升 / 星炬 / 补给空投 |
| 装备 | 锻造幸运、强化起始值、强化衰减、腐蚀词条 |

### 5.3 后期成长靠乘区（核心结论）

参考项目实测：从 Lv.16 到 Lv.29，
**怪物血量涨了 242 倍，玩家主属性只涨了 10%**（2734 → 2996）。
全部来自乘区：

| 乘区 | 起点 | 终点 |
|---|---|---|
| 双重伤害概率 | 0% | **95.5%** |
| 暴击率 / 暴击倍率 | 0% / 50% | 14% / **240%** |
| 再打一次概率 | 0% | 39% |
| 技能伤害乘区 | ×1.0 | **×2.6** |
| 技能冷却速度 | ×1.0 | ×1.8 |
| 主技能段数 | 2 | **18**（×9） |
| 敌人生命倍率（削弱） | ×1.0 | **×0.8** |

**设计纪律**：
1. 主属性只负责前 15 关，之后退居次要
2. 成长必须摊在 **6–8 个彼此独立的乘区**上，不能只靠一个
3. 「削弱敌人」要算作一条正规成长线

### 5.4 用「公式字符串」驱动全部内容（工程上最重要的一条）

参考项目**没有任何一处把数值写死在代码里**，
全部是 ScriptableObject + 公式字符串：

```csharp
class StatValueCostEquations {
    StatInfo stat;
    string   valueEquation;   // 数值成长公式
    string   costEquation;    // 升级花费公式
}

class TreeNodeInfo {
    string NodeName, NodeDescription;
    List<string> NodeValueEquation;    // 每级给多少
    List<string> NodeCostEquation;     // 每级花多少
    List<Currencies> _nodeCostCurrencies;  // 用哪种货币买
}

class MasteryInfo {
    string LevelUpCostEquation;
    string MainValueEquation;
    string MainSuffix;
    int    MainDecimals;
}
```

**建议本作完全照搬这套架构**：

- 数据类清单：`EnemyInfo` / `FactionInfo` / `FactionSkillInfo` /
  `SkillInfo` / `SkillDetailInfo` / `SkillPowerInfo` /
  `CodexInfo` / `CodexNodeInfo` / `AdeptaInfo` / `RelicPerkInfo` /
  `ItemInfo` / `ItemStatsInfo` / `SealStatInfo` / `WeaponInfo` /
  `ProjectileInfo` / `ExtractionConfig`
- 公式字符串支持 `1.66^level`、`level^1.5`、`50*level` 这类表达式
- 每个《圣典》节点自带货币选择（12 种货币精细分配）

> 本作要承载 273 属性 / 168 节点 / 15 技能 / 9 机构，
> **不做这套架构就一定会失控。**

## 六、关卡与难度（沿用结构与曲线）

### 6.1 关内结束条件：歼灭配额，不是计时器

参考项目单关目标时长设计在 **4–5 分钟**（Lv.1–6 实测均值 271 秒），
但因结束条件是**杀够 N 只**，玩家变强后耗时自然压缩（Lv.9 只用 84 秒）。

**配额从 Lv.1 的 128 只涨到 Lv.29 的 668 只。**

**刷怪是按「距离」而不是「时间」触发的**（参考项目 `EnemiesManager`
的 `SpawnPackEvery_Distance`）：玩家每推进一段距离就生成一批怪
（Pack），清空这一批就结算一次里程碑。

> 这个设计比计时刷怪好得多：**玩家的推进速度直接决定节奏**。
> 打得快 = 更快遇到下一批 = 更快通关；
> 反过来，卡住了也不会被无限刷出的怪堆死。
> 本作应当照搬，不要改成计时器。

40K 解释：舰船在该轨道的**停留窗口**是固定的，
但你的清剿效率决定了要打几波 —— 打得快就早收工。

### 6.2 难度成长曲线（直接复用）

单怪血量的环比倍率（已按 attempt 加权修正 overkill 溢出）：

| 区间 | 总倍率 | 每关倍率 | 性质 |
|---|---|---|---|
| 1 → 9 | ×559.6 | **×2.205 / 关** | 教学期陡坡 |
| 9 → 15 | ×7.3 | **×1.393 / 关** | 中段稳态 |
| 15 → 17 | ×2.0 | ×1.428 / 关 | 末期 |
| **1 → 29 全程** | **×1,516,275** | **×1.662 / 关** | 纯指数 |

> **不是线性，是「前陡后缓的指数」。** 整体约 **×1.66^关卡**。
> 前 9 关做成 ×2.2/关的陡坡，快速给正反馈；
> 中段回落到 ×1.39–1.54/关。30 关累计血量跨度约 **150 万倍**。

### 6.3 守卫关（Boss 关）

**每 10 关一个守卫 BOSS**（沿用参考项目结构）。
参考项目共 **40 关**（见下方口径说明），本作建议：

| 关卡 | BOSS | 阵营 |
|---|---|---|
| Lv.10 | 战争头目（兽人） | Orks |
| Lv.20 | 混沌领主 | Chaos |
| Lv.30 | 暴君（泰伦） | Tyranids |
| Lv.40 | **大魔**（最终 BOSS） | Chaos / Warp |

**每关入场需要消耗亚空间信标**（原 Portal 系统）。

> **口径说明**：参考项目的平衡测试存档只跑到 Lv.30，一度让人以为上限是 30。
> 但 DLL 的成就系统里写着 `LevelMilestone = 40`，
> 并有一个成就叫 `ReachLevel40` —— **实际是 40 关**。
> 这是本次逆向中「测试数据截断值 ≠ 设计上限」的一个教训。

### 6.4 参考项目的三个节奏失误 —— 本作必须避开

这三条是从实测数据里挖出来的真实教训，**直接照抄会重蹈覆辙**：

**① 解锁爆发不要撞上难度陡坡**

参考项目 Lv.7 同时放出 3 个主动技能 + 血量环比 ×2.08，
导致同一套装备**连败 3 次**。

> 本作的技能解锁点要**错开**难度陡坡：
> 放出新技能的那一关，血量倍率应低于相邻关的平均值。

**② 不要让「主属性 → 乘区」的转型变成隐形门槛**

参考项目 Lv.16 血量只涨 ×1.53，但属性需求跳了 **×10.6** ——
玩家必须自己悟出该转型了，游戏没有任何提示。

> 本作要在转型关**加显式引导**：
> 例如让舰船广播「检测到敌方生物质密度上升，建议更换弹药配方」，
> 并给一次免费的词条重铸。

**③ 生存属性不要给得太慷慨**

参考项目 Lv.8–28 共 **20 关零死亡**，中期完全失去威胁感。

> 本作的生存属性成长要**明显慢于**输出属性成长，
> 目标：每 5 关至少出现一次「差点死掉」的体验。

## 八、装备与词缀（换皮）

### 8.1 装备结构（完全沿用）

```
BaseLevel / BaseValue / MinValue / MaxValue    基础值与浮动区间
ItemRarity                                     稀有度 0-3
Improvements / ImprovementFailed               强化次数 / 是否失败过
ImprovementChanceExemption                     强化保底次数
DoubleImproveChance                            双倍强化概率
ExtraStatsFromScroll / ScrollStatValuesMultiplier  卷轴加词条
CorruptAddedStats / IsCorrupted                腐蚀改造
```

三种改造手段：**强化（会失败）**、**重铸**、**腐蚀**。

**40K 表现**：
- 强化 = **涂油与祝圣**（失败 = 「机魂拒绝了你」）
- 腐蚀 = **亚空间腐化**（强力但会增加腐化值）
- 重铸 = **拆解重装**

**锻造常量**（参考项目实测值，可作为本作调参起点）：

```
词条数值加成档      +25%       （解锁链第 5 级给的）
幸运加成档          +500%
首次锻造产出        3 件
传说保底等级        8          （第 8 级锻造必出传说）
```

### 8.1b 卷轴系统（8 种，参考项目有而初稿遗漏）

卷轴是**一次性消耗品**，作用于「下一次锻造 / 下一次造符」，
可以拖到锻造台上激活。共 8 种，分两线：

| 物品卷（作用于装备） | 符文卷（作用于印记） |
|---|---|
| **精炼** Refinement | **铭刻** Inscription |
| **回火** Tempering | **增幅** Amplification |
| **精通** Mastery | **升格** Ascension |
| **完美** Perfection | **溢流** Overflow |

**数值参考**（参考项目常量）：

```
符文卷固有词缀数倍率    ×1.2
物品卷词条数值倍率      ×1.5
物品卷强化成功率倍率    ×1.3
卷轴强制稀有度          传说
```

**40K 表现**：**圣油与祷文** —— 在锻造前涂抹不同的圣油，
会对下一次锻造产生不同的祝福。

> 卷轴系统解决了一个典型的刷取游戏问题：
> **「我攒了一堆材料但不想现在用」**。
> 卷轴让玩家可以在**关键时刻**把一次锻造的品质拉高，
> 而不是被随机数支配。

### 8.2 武器类型与类别（直接对应）

原 6 种武器 / 3 个类别，本作**正好也有 6 种极具 40K 特色的武器**：

| 武器 | 类别 | 词缀前缀 |
|---|---|---|
| **链锯剑** Chainsword | 近战 | `Chain_` |
| **雷霆锤** Thunder Hammer | 近战 | `Hammer_` |
| **风暴盾** Storm Shield | 近战 | `Shield_` |
| **电浆枪** Plasma | 能量 | `Plasma_` |
| **热熔枪** Melta | 能量 | `Melta_` |

### 8.3 词缀双轨制（完整表，已从 DLL 常量还原）

词缀分两轨：**固有词缀**绑定武器类型（保证主题一致性），
**随机词缀**走通用池（提供刷取动力）。

**武器固有词缀 —— 每种武器恰好 4 条**（共 24 条）：

| 武器 | 固有词缀（4 条） |
|---|---|
| **链锯剑** | 双斩概率 / 连击伤害 / 顺劈伤害 / 首击伤害 |
| **雷霆锤** | **震荡半径 / 每命中一个敌人增加伤害 / 余震伤害 / 碎裂伤害** |
| **电浆枪** | 额外连锁 / 分叉概率 / 每段连锁伤害 / 首目标伤害 |
| **热熔枪** | 双落概率 / 陨击弹幕概率 / 精英伤害 / 处决伤害 |
| **风暴盾** | 主动回复 / 到期治疗 / 敌人攻速削减 / 武器伤害光环 |
| **战旗** | 攻速加成 / 武器急速 / 三倍伤害概率 / 弹匣回填概率 |

> **雷霆锤这一组堪称完美**：`震荡半径` + `每命中一个敌人增加伤害` +
> `余震伤害` + `碎裂伤害` —— 四条全部是「锤子砸下去」的物理语言，
> 而且 `每命中一个敌人增加伤害` 天然鼓励**往人堆里砸**，


| 稀有度 | Implicits | Explicits |
|---|---|---|
| Epic | 2 | 2 |
| Legendary | 2 | 3 |

> `Hammer_ConcussiveChance` 是按命名规律**推测**的例子，并不存在。

### 8.4 圣化（原 Shaping 符文系统）

- 2–3 个槽位，每槽是「武器 + 等级 + 镶嵌的印记」
- 印记有 **固有（Implicit）** 和 **随机（Explicit）** 两层
- 印记有三个作用目标：`Attack` 攻击 / `Buff` 增益 / `All` 全部
- 增益类武器是**周期性触发**（`BuffPhase`: Cooldown → Active）

**40K 表现**：**圣化印记** —— 在武器上刻下帝皇的祷文与封印，
不同的封印给不同的机魂加成。

### 10.1 经济曲线 —— 本作必须主动调控

参考项目实测：金币环比 **×2.2~2.5 / 关**，
**快过怪物血量的 ×1.66**，导致「金币/血量」比从 0.36 涨到 15.1（**×42**）——
后期经济完全失控。

**本作的对策**：

1. **金币环比压到 ×1.5–1.7**，略低于血量增长
2. **后期成本项要跟上**：锻造/圣化的花费曲线要对齐血量曲线
3. **引入消耗池**：亚空间信标可以「超频」消耗（花信标换一次额外轨道打击）
4. **每 5 关做一次经济体检**：算「玩家当前收入 / 下一级关键升级花费」，
   该比值应稳定在 **2–4 关的收入**，不应随时间漂移

## 十一、发布、成就与规模控制

非商用项目没有商业化，但有**三件同等重要的事**：
发到哪里、成就怎么设计、以及**做到多大**。

### 11.1 发布方式

| 渠道 | 适合度 | 说明 |
|---|---|---|
| **itch.io** | ★★★★★ | 免费、无审核门槛、同人项目的默认去处 |
| **GitHub Releases** | ★★★★ | 适合开源，但玩家发现成本高 |
| **Steam（免费游戏）** | ★★ | 需 $100 上架费 + 通过审核；**IP 风险最高的渠道** |

**建议走 itch.io。** 它没有审核关卡，同人项目生态成熟，
而且不像 Steam 那样会把 DMCA 投诉直接变成下架 + 封号。

> ⚠️ 无论走哪个渠道，**只要公开分发，就有被投诉下架的可能**。
> 详见附录 C 的说明。

### 11.2 成就系统（参考项目实测 9 个）

| 原成就 | 本作版本 |
|---|---|
| `RecruitArcher` | 首次机仆化成功 |
| `UnlockJobs` | 解锁机构系统 |
| `UnlockCrafting` | 解锁锻造 |
| `UnlockMining` | 解锁开采 |
| `UnlockShaping` | 解锁圣化 |
| `UnlockMastery` | 解锁晋升 |
| `UnlockStar` | 解锁星炬 |
| `GainLegendaryBowArmor` | 获得一件传说装备 |
| `ReachLevel40` | 通关全部 40 个战区 |

**参考项目的成就设计有一处值得注意**：9 个成就里 **7 个是系统解锁成就**
—— 成就系统承担了一部分**新手引导**职能：解锁一个系统就弹一个成就，
既是奖励也是「你进入新阶段了」的仪式感。
而不是把成就塞满「击杀 10000 只怪」这类后期挑战。

**非商用项目建议做成游戏内成就**（不接平台 API），
省掉 Steamworks 集成的工程量。

### 11.3 规模控制 —— 非商用项目最重要的一节

参考项目是**商业产品**：560 个类型、39 个 Manager、273 个属性、
168 个天赋节点、40 关。**一个人做，必须砍。**

**建议的砍法（按「保留什么」排序，从最不能砍的开始）**：

| 优先级 | 内容 | 理由 |
|---|---|---|
| **必留** | 轨道打击手感（5 段反馈） | 核心体验，砍了就不是这个游戏 |
| **必留** | 四桶数值模型 + 公式字符串架构 | 架构定错后期推倒重来 |
| **必留** | 1 个机构 × 3 技能 | 有技能才叫 build |
| **必留** | 10 关 + 1 个守卫 BOSS | 能完整玩一局 |
| 建议留 | 《圣典》树（**砍到 30–40 节点**，不是 168） | 有成长感即可，168 个是做不完的 |
| 建议留 | 装备 + 词缀（**12 条词缀足够**，不是 37 条） | 刷取循环的最小闭环 |
| 可砍 | 4 个机构、4 个阵营 | 内容量，以后加 |
| 可砍 | 开采 / 圣化 / 晋升 / 星炬四条链 | 保留锻造一条即可 |
| 可砍 | 卷轴系统 | 锦上添花 |
| 可砍 | 腐化系统 | 差异化卖点，但属于 P3 |

**一个人能做完的规模参考**：
**1 个机构 + 3 技能 + 30 节点圣典 + 12 条词缀 + 10 关 + 1 个 BOSS**。
这已经能跑通完整的「打 → 掉 → 变强 → 再打」循环，
而且能让别人看懂这个游戏是什么。

> **砍内容不是砍体验。** 上面这一刀砍掉了约 85% 的内容量，
> 但核心的「轨道打击 + 机仆化 + 刷装备」三件事一个没少。
> 剩下的以后想加随时能加 —— 你手上这份文档就是完整的扩写蓝图。

## 十二、40K 主题带来的新设计机会

以下三条是**题材独有的红利**，参考项目没有对应物，
但与本作的系统架构天然兼容 —— 建议作为差异化卖点。

### 12.1 腐化系统（Corruption）

40K 最标志性的设定就是**使用亚空间力量必然付出代价**。

**机制**：玩家的「灵能系」技能与「腐蚀改造」装备会累积**腐化值**。

| 腐化区间 | 效果 |
|---|---|
| 0–25% | 无影响 |
| 25–50% | 灵能技能 +15% 伤害，但屏幕边缘出现低语 |
| 50–75% | 双重伤害概率大幅提升，但敌人有概率**变成友军后又叛变** |
| 75–100% | 极强的战力，但每关结束有概率**永久损失一件装备** |

**为什么这个设计好**：
- 它是**玩家自己选的**风险，不是随机惩罚 —— 符合现代 roguelite 的设计伦理
- 它直接复用了现有的「乘区」结构（腐化就是一个额外的乘区层）
- 它给「腐蚀改造」这个已有机制赋予了叙事重量

### 12.2 机仆化的情绪价值

参考项目的驯服系统数值上被埋没了，但它**在 40K 语境下有巨大的情绪价值**：

> 把刚刚还在撕咬你队友的泰伦战士，**当场改造成替你挡子弹的机仆** ——
> 这个画面的冲击力远超「驯服一只狼」。

**建议把机仆化做成核心卖点之一**，并给足数值权重
（目标伤害占比 8–12%，参考项目 < 0.6%）。

### 12.3 轨道打击的「重量感」

这是参考项目因题材所限做不到的（箭雨的重量感天然弱于舰炮）。

**具体做法**：
- 标记 → 延迟 → 光柱 → 音爆 → 冲击波 → 焦痕，**完整的 5 段反馈**
- 齐射时多道打击**错开 0.1 秒**落下，形成**鼓点节奏**
- 不同武器类型给**不同的落地音色**（雷霆锤 = 低频轰鸣，热熔 = 灼烧嘶声）
- 屏幕震动强度与**当次打击伤害成正比**

## 附录 C：关于「非商用」的一点提示

本项目定位为非商用同人作品，因此无需走授权流程。
但有几点事实值得知道，**万一以后想公开分发**：

- **「非商用」不是版权豁免。** 它只是合理使用四要素里的**一条**，
  不是安全港。免费分发同人作品通常比商业分发温和，但不等于没有风险。
- **真正的风险点是「公开分发」，不是「有没有收钱」。**
  自己玩、给朋友传，实际风险接近于零；
  挂到公开渠道就可能收到投诉。
- **商标与版权是两回事。** 商标法管的是「商业使用 + 混淆可能」，
  免费作品较难触发；但版权（角色、设定、美术）不看收不收钱。
- 权利方历史上对**免费的**同人项目也发过停止侵权函。
  不同权利方的态度差别很大。

**实操建议**：

1. 优先发 **itch.io**（无审核门槛），避免 Steam（审核 + 下架风险叠加）
2. **不要用官方美术、音乐、音频素材** —— 自己画、自己录，
   这能规避掉大部分的版权风险
3. 标题里保留 `fan-made` / `非官方` 字样，避免让人误以为是官方作品
4. 别收钱、别接广告、别上众筹

> 这一节不是法律意见。真要公开发布前，值得花半小时查一下
> 该权利方最新的同人政策（很多公司会专门发一份 fan content policy）。
